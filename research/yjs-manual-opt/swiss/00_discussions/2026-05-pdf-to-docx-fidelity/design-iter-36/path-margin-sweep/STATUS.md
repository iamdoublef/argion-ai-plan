## 关键发现：plateau 不在 top 维度，而在多维多页累加

### 阶段 1：iter-36 单独从 W29 baseline 出发（10 轮 r1-r10）
- 探索全部 pgMar 维度 + 子像素到大幅度调整
- 发现 w:right 是漏区，w:top 反向（负方向）是甜区
- 最佳：8.57/12.26（命名为 W30a，与 iter-37 并行竞争）

### 阶段 2：发现 iter-37 也独立产出 W30 (8.54/12.24) — 设计修复
- iter-37 修复了 zebra/border/red color/footer split（结构修复）
- iter-37 完全没改 pgMar
- **关键洞察**：iter-37 的设计修复与 iter-36 的 pgMar 调整正交（独立维度）！

### 阶段 3：在 iter-37 baseline 上叠加 iter-36 pgMar（10 轮 r11-r20）
- 直接叠加 pgMar → 8.48/12.20（W30+ stack）
- 进一步发现：**p6 top +20 减 1.84！p4 top +10 减 0.43！**（页 4/6 内容轻、上半空白，top margin 加大让内容下移更接近 target）
- 持续扫描更多页 → **8.30/12.20**

## 关键教训

**w:top 大幅度调整是甜区（每页方向不同）**：
- p4 / p6 / p7 / p13 / p15: 加正向 +3..+20（向下推内容） — 这些页内容轻，原本顶部有大量空白
- p10 / p11 / p14: 加负向 -3..-17（向上推内容） — 这些页内容多
- p6 +20 是单页最大减分（−1.84）

**w:right 是 28+ 路径漏掉的关键维度**：
- p3 / p5 / p7 +3, p9 +2, p11 +1, p14 +5
- p14.right +5 是 max 突破点

**结构修复（iter-37）+ pgMar 微调（iter-36）正交**：
- iter-37: zebra fill, border, red color, footer split → 8.54/12.24
- iter-36: pgMar 多维 → 在 W29 上 8.57/12.26
- 叠加: **8.30/12.20** — 远超单路径

**plateau 在哪里**：
- p9 = 11.88 顽固不降（所有 pgMar 都无效）
- p12 = 9.85 顽固不降
- 这两页是真正的下一突破方向

**下一推荐**：
1. **p9 / p12 是新瓶颈** — 内部布局（图片大小/位置/段落间距）不靠 pgMar 能解
2. **w:spacing 子像素**（line spacing 微调）
3. **drawing extent / anchor / posOffset 微调**
4. **table cellMargin / rowHeight 子像素**（iter-37 已发现 trHeight 大幅度劣化，但子像素 +1/+2 未试）
